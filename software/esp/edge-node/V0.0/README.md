# ESP32-CAM Capture (ESP-IDF)

التقاط صورة كل دقيقة، ومقارنتها بآخر صورة محفوظة، والاحتفاظ بها فقط إذا كان هناك تغيير، ثم إرسالها إلى الخادم أو قاعدة البيانات.

## التوصيلات

| العنصر | التوصيل |
|---|---|
| زر RESET خارجي | EN ↔ GND (على التوازي مع زر RST الأصلي) |
| زر BOOT خارجي | IO0 ↔ GND |
| LED1 حالة | GPIO13 → 330Ω → LED → GND |
| LED2 تصوير | GPIO14 → 330Ω → LED → GND |
| LED3 حفظ | GPIO15 → 330Ω → LED → GND |
| البطارية | 18650 → TP4056 → مفتاح → MT3608 (5.0V) → رجل 5V + GND، ومكثف 470–1000µF |

> لا تستخدم بطاقة SD مع هذه الأرجل، لأن GPIO 13 و14 و15 تشترك معها.

## معنى الأضواء

- **LED1 (GPIO13):** ومضة كل ثانية تعني أن WiFi غير متصل. إذا كان مضاءً بشكل ثابت فهو متصل.
- **LED2 (GPIO14):** يضيء أثناء التقاط الصورة.
- **LED3 (GPIO15):** ومضتان تعنيان أنه تم الاحتفاظ بالصورة. خمس ومضات سريعة تعني أن التقاط الصورة فشل.
- **الأضواء الثلاثة معاً تومض:** يوجد خطأ في الكاميرا أو PSRAM، وستعيد اللوحة التشغيل.

## الفتح في VS Code (إضافة ESP-IDF)

1. افتح المجلد `esp32cam_capture` من: File → Open Folder.
2. اضغط `Ctrl+Shift+P` ثم اختر **ESP-IDF: Set Espressif Device Target**، واختر **esp32** ثم *ESP32 chip (via ESP USB Bridge)* أو أي خيار مناسب.
3. اضغط `Ctrl+Shift+P` ثم اختر **ESP-IDF: SDK Configuration Editor (menuconfig)**، وافتح قسم **ESP32-CAM Capture Settings**:
   - WiFi SSID وكلمة السر
   - مدة الالتقاط (افتراضياً 60 ثانية)
   - عتبة التغيير (افتراضياً 2.0%)
   - تفعيل الرفع (Upload) ورابط الخادم
4. اضغط **Build** (رمز الأسطوانة في الشريط السفلي). عند أول بناء ستُحمَّل مكتبة `esp32-camera` تلقائياً من Component Registry.
5. اختر منفذ COM، ثم اضغط **Flash** (رمز البرق)، ثم **Monitor**.
   - إذا كنت تستخدم لوحة ESP32-CAM-MB، فالبرمجة تتم تلقائياً.
   - إذا كنت تستخدم محول USB-TTL: اضغط BOOT واستمر بالضغط، ثم اضغط RESET وأفلته، ثم أفلت BOOT، وبعدها ابدأ الرفع. بعد انتهاء الرفع اضغط RESET.

## خوارزمية المقارنة

1. تُصغَّر صورة JPEG إلى 1/8 من حجمها (100×75 بكسل لدقة 800×600) وتُحوَّل إلى تدرجات رمادية.
2. يُطرح فرق الإضاءة العام، حتى لا يُعتبر تغيّر الضوء التدريجي "حركة".
3. يُحسب البكسل "متغيراً" إذا كان الفرق فيه أكبر من `PIXEL_DIFF_THRESHOLD` (القيمة الافتراضية 25).
4. إذا تجاوزت نسبة البكسلات المتغيرة `CHANGE_PERCENT_X10` (القيمة الافتراضية 20، أي 2.0%) تُحفظ الصورة وتصبح هي المرجع الجديد. غير ذلك تُحذف.

المقارنة تكون دائماً مع **آخر صورة تم الاحتفاظ بها**، وليس مع آخر صورة التُقطت. بهذا لا تفوتك التغيرات البطيئة.

## معاينة الصور للتجربة (بدون سيرفر)

عند تفعيل `PREVIEW_ENABLE` (مفعّل افتراضياً) تُحفظ كل صورة جديدة يحتفظ بها البرنامج **مؤقتاً في PSRAM**
(آخر 8 صور افتراضياً `PREVIEW_COUNT`). لا يُكتب شيء على الفلاش، والصور تُمسح عند إعادة التشغيل.

- **الوضع الافتراضي (بدون راوتر):** اللوحة تنشئ شبكتها الخاصة `EdgeNode-CAM` وكلمة السر `12345678`.
  اتصل بها من الهاتف وافتح `http://192.168.4.1/`. (يمكن تغييرها من menuconfig → WiFi mode).
- في وضع الاتصال بشبكة موجودة (STA): افتح `http://<IP-اللوحة>/` (يظهر الرابط في Monitor بعد الاتصال).
- تعرض الصفحة الصور من الأحدث للأقدم مع الوقت ونسبة التغيير، وتتحدث تلقائياً.
- `http://<IP-اللوحة>/latest.jpg` يعرض آخر صورة فقط.

## الإرسال إلى قاعدة البيانات

الصور المحفوظة تُوضع في طابور داخل PSRAM (حتى 4 صور)، ثم تُرسل بطلب HTTP POST:

```
POST <UPLOAD_URL>
Content-Type: image/jpeg
X-Device-Id: esp32cam-01
X-Timestamp: <unix seconds>
<JPEG bytes>
```

- إذا فشل الإرسال تبقى الصورة في الطابور وتُعاد المحاولة كل 10 ثوانٍ.
- إذا امتلأ الطابور تُحذف أقدم صورة.

### خادم تجريبي (SQLite)

```
cd server
python upload_server.py
```

بعد تشغيله ضع في menuconfig الرابط: `http://<IP-جهازك>:8000/upload`. لمعاينة آخر صورة افتح `http://<IP>:8000/latest.jpg`.

لاحقاً يمكنك استبدال هذا الخادم بـ Supabase أو Firebase أو أي API آخر، بشرط أن يستقبل طلب POST بصيغة `image/jpeg`. الرابط يدعم `https://` (شهادات الجذر مضمنة في البرنامج).
