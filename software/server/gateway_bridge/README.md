# جسر ESP — من الكاميرا إلى الداشبورد

يربط برمجة العقدة الحالية (`referance-project/Edge-Node`) بالداشبورد **دون أي تعديل على البرمجة الثابتة**.

```
ESP32-S3 CAM  ──WiFi: EdgeNode-CAM──►  الحاسوب
(وضع AP، آخر 8 صور                       esp_bridge.py يقرأ http://192.168.4.1/
 في PSRAM على http://192.168.4.1/)            ↓  POST /api/captures/  +  /api/heartbeats/
                                         الداشبورد ← طابور اليولو ← مدير اليولو
```

البرمجة في وضعها الافتراضي (`CAM_WIFI_AP`) تبث شبكتها الخاصة، وتعرض الصور التي تغيّر فيها المشهد على صفحة صغيرة. الجسر يقرأ هذه الصفحة كل بضع ثوانٍ، وينزّل كل صورة جديدة، ويرسلها إلى الخادم. فتظهر في **الصور والكشف** وتدخل طابور اليولو مباشرة.

لا يحتاج أي مكتبة إضافية، ويعمل ببيئة Django الحالية.

## التشغيل خطوة بخطوة

1. **سجّلوا العقدة مرة واحدة:** من الداشبورد **العقد ← إضافة عقدة**، بالرمز نفسه الموجود في `Device ID` في menuconfig. الافتراضي هو `esp32cam-01`.
2. **شغّلوا الخادم:**
   ```
   cd backend
   ..\bin\python.exe manage.py runserver
   ```
3. **شغّلوا اللوحة،** ثم اربطوا الحاسوب بشبكتها: `EdgeNode-CAM`، كلمة السر `12345678`.
4. **شغّلوا الجسر في نافذة ثانية:**
   ```
   cd gateway_bridge
   ..\bin\python.exe esp_bridge.py
   ```
5. **افتحوا** `http://127.0.0.1:8000/captures/` لتظهر الصور.
6. **لتشغيل اليولو عليها:** `python manager.py run` من مجلد `yolo_manager`. انظروا [README مدير اليولو](../yolo_manager/README.md).

عند ربط الحاسوب بشبكة اللوحة ينقطع عنه الإنترنت، لكن الداشبورد يبقى يعمل لأنه على الحاسوب نفسه (`127.0.0.1`).

## ما يظهر في نافذة الجسر

```
13:12:41 INFO    Board "esp32cam-01" reachable, 3 image(s) in its gallery.
13:12:42 INFO    Image #1 (first image, 134 KB) -> capture 686
13:12:46 INFO    Image #4 (change 3.7%, 49 KB) -> capture 689
```

## الخيارات

| الخيار | الافتراضي | الوصف |
|---|---|---|
| `--esp` | `http://192.168.4.1` | عنوان اللوحة. في وضع STA ضعوا عنوان IP الذي يظهر في Monitor |
| `--node` | Device ID اللوحة | رمز العقدة في الداشبورد |
| `--poll` | 5 | ثوانٍ بين كل فحص |
| `--heartbeat` | 60 | ثوانٍ بين نبضات «العقدة متصلة» |
| `--once` | — | يرسل ما في اللوحة الآن ثم يتوقف |
| `--api` / `--key` | `http://127.0.0.1:8000/api` / `dev-api-key` | عنوان الخادم ومفتاحه، أو متغيرا البيئة `DAMASCUS_EYE_API` و`DAMASCUS_EYE_API_KEY` |

## سلوك الجسر

- **لا تكرار:** يحفظ بصمة (SHA-256) كل صورة أرسلها في `.seen-<العقدة>.json`. إعادة تشغيل الجسر أو اللوحة لا ترسل الصورة نفسها مرتين.
- **انقطاع اللوحة أو الشبكة:** يطبع تنبيهاً مرة واحدة، ويستمر بالمحاولة. إذا توقفت النبضات 30 دقيقة تظهر العقدة «منقطعة» في الداشبورد، وهذا هو فحص السرقة.
- **عقدة غير مسجلة أو مفتاح خاطئ:** يتوقف برسالة تشرح ما يجب فعله.

## حدود وضع AP الحالي

- **الوقت:** اللوحة بلا إنترنت فلا تعرف الوقت، وتعرض «time not synced». الجسر يستخدم وقت وصول الصورة إلى الحاسوب، وهو دقيق ضمن ثوانٍ لأن الفحص كل 5 ثوانٍ.
- **8 صور فقط في ذاكرة اللوحة** (`PREVIEW_COUNT`)، وتُمسح عند إعادة التشغيل. إذا كان الحاسوب مفصولاً لفترة تكفي لالتقاط أكثر من 8 صور متغيرة، تضيع الأقدم منها. مع الالتقاط كل 60 ثانية تكفي هذه السعة 8 دقائق على الأقل. يمكن رفع `PREVIEW_COUNT` حتى 30 من menuconfig.
- **الجسر يقرأ صفحة HTML.** إذا تغيّر شكل الصفحة في `index_get()` داخل `main.c`، يجب تحديث النمط `ENTRY` في `esp_bridge.py`.

## لاحقاً: الإرسال المباشر عبر راوتر (وضع STA)

البرمجة تدعم أيضاً رفع الصور بنفسها عند الاتصال براوتر (`UPLOAD_ENABLE`)، بصيغة `image/jpeg` مع الترويستين `X-Device-Id` و`X-Timestamp`. الواجهة الحالية `/api/captures/` تتوقع صيغة مختلفة (multipart مع مفتاح API). عند الانتقال إلى ذلك الوضع نضيف نقطة استقبال تقبل صيغة البرمجة مباشرة، فلا يعود الجسر ضرورياً.
