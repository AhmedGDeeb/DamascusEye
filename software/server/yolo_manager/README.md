# مدير اليولو — Damascus Eye

برنامج مستقل يأخذ الصور من طابور الكشف في الخادم، ويشغّل عليها موديل YOLO أو أكثر، ثم يرسل النتائج إلى قاعدة البيانات فتظهر الصناديق في الداشبورد.

```
العقدة ← البوابة ← الخادم (Capture: pending)
                         ↓  POST /api/yolo/claim/
                    مدير اليولو  ←  YOLO26 / YOLOE
                         ↓  POST /api/yolo/results/<id>/
                    الداشبورد (الصناديق + هل الجسم على الرصيف)
```

لا يتصل بقاعدة البيانات مباشرة، بل عبر الواجهة البرمجية فقط. لذلك يعمل على الحاسوب نفسه أو على جهاز آخر فيه كرت شاشة.

## التثبيت

بيئة افتراضية منفصلة عن بيئة Django، لأن PyTorch كبير (1 إلى 2 غيغابايت).

> **مهم:** بيئة Django الحالية مبنية على Python المرفق مع Inkscape. هذه نسخة MinGW، وPyTorch لا يدعمها، فلن يُثبَّت YOLO عليها أبداً. أنشئوا بيئة المدير من **Python الرسمي** من python.org، وهو موجود على الجهاز كـ `py -3.14`.

```
cd yolo_manager
py -3.14 -m venv .venv
.venv\Scripts\activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
```

إذا توفر كرت NVIDIA، ثبّتوا نسخة PyTorch الخاصة بـ CUDA بدل سطر `cpu`.

تُنزَّل أوزان الموديل (مثل `yolo26n.pt`) تلقائياً عند أول تشغيل.

## التشغيل

الخادم يجب أن يعمل أولاً (`manage.py runserver`).

| الأمر | ماذا يفعل |
|---|---|
| `python manager.py run` | يعالج الطابور باستمرار، ويفحصه كل 5 ثوانٍ |
| `python manager.py run --once` | يعالج ما في الطابور ثم يتوقف |
| `python manager.py ingest --node N01 صور_الرصيف\` | يرفع صوراً من الهاتف كأن العقدة N01 التقطتها |

### مقارنة الموديلات على الصور نفسها

```
python manager.py run --once --model yolo26n.pt --model yoloe-26s-seg.pt ^
    --prompts "goods display,plastic chair,table,market stall,cardboard boxes,motorcycle,person"
```

كل موديل يُحفظ كتشغيل منفصل، ويظهر كتبويب في صفحة الصورة في الداشبورد. YOLO26n يعرف أصناف COCO الثمانين فقط، فلا يرى «البضائع المعروضة». أما YOLOE فيكشف ما تكتبونه في `--prompts`.

### كشف الرصيف تلقائياً (بدون تدريب)

مع كل صورة يكتشف المدير الرصيف نفسه بموديل جاهز، ويلوّنه **بالبنفسجي** في الداشبورد. ثم يقرر لكل جسم (شخص، كرسي، دراجة نارية…) هل يقف على الرصيف.

| `--sidewalk` | الموديل | ملاحظات |
|---|---|---|
| `yoloe` (الافتراضي) | `yoloe-26s-seg.pt` بالكلمتين "sidewalk" و"pavement" | يغطي الأرصفة والمساحات المرصوفة للمشاة جيداً |
| `sem` | `yolo26n-sem.pt` (مدرّب مسبقاً على Cityscapes) | يميّز الرصيف عن الشارع إذا كان بينهما حجر رصيف واضح، لكنه قد يعدّ الساحات المرصوفة «طريقاً» |
| `off` | — | يعتمد فقط على منطقة الرصيف المرسومة يدوياً |

**كيف يُقرَّر «على الرصيف»:**
1. **قناع الرصيف:** تُملأ الفراغات التي يتركها الناس والأشياء الواقفة عليه، فيصبح القناع الرصيف كاملاً مع ما فوقه.
2. **شريط تحت كل جسم:** يُفحص شريط ضيق عند قاعدته (الأقدام أو العجلات أو أرجل الطاولة). إذا كان 40% منه أو أكثر رصيفاً، يُعد الجسم «على الرصيف».

**مقارنة الطريقتين على صوركم:** شغّلوا مرة بـ `--sidewalk yoloe` ومرة بـ `--sidewalk sem`، بعد إعادة الصور إلى الطابور. كل تشغيل يظهر كتبويب منفصل في صفحة الصورة، مع اسم موديل الرصيف.

على صورة اختبار (ممر مشاة مرصوف بلا حجر رصيف) وجد YOLOE الرصيف بنسبة 29% من الصورة، بينما عدّه Cityscapes طريقاً ووجد 3% فقط. لذلك YOLOE هو الافتراضي. جرّبوا الاثنين على صور أرصفة دمشق قبل اعتماد أحدهما.

`--sidewalk-conf` (الافتراضي 0.1) هو حد الثقة لقناع YOLOE. ثقة الأرصفة منخفضة عادةً (0.1 إلى 0.3)، فلا ترفعوه كثيراً.

### خيارات مفيدة

| الخيار | الافتراضي | الوصف |
|---|---|---|
| `--conf` | 0.25 | حد الثقة الأدنى |
| `--imgsz` | 640 | حجم الصورة عند الكشف |
| `--classes` | الكل | الاحتفاظ بأصناف معينة فقط، مثل `"person,chair,dining table,motorcycle"` |
| `--device` | تلقائي | `cpu` أو `0` لأول كرت شاشة |
| `--batch` | 4 | عدد الصور في كل طلب حجز |
| `--api` | `http://127.0.0.1:8000/api` | عنوان الخادم، أو متغير البيئة `DAMASCUS_EYE_API` |
| `--key` | `dev-api-key` | مفتاح الواجهة، أو متغير البيئة `DAMASCUS_EYE_API_KEY` |

## تجربة سريعة بصور الهاتف (بدون عقد)

1. في الداشبورد: **العقد ← إضافة عقدة** برمز `N01`، ثم **رسم منطقة رصيف** على أول صورة.
2. `python manager.py ingest --node N01 C:\path\to\photos`
3. `python manager.py run --once`
4. افتحوا **الصور والكشف** في الداشبورد.

إذا رُفعت الصور قبل رسم منطقة الرصيف، فلن يُعرف أي الأجسام على الرصيف. ارسموا المنطقة، ثم أعيدوا الكشف من زر «إعادة الكشف» في صفحة الصورة، أو من لوحة الإدارة: Captures ← اختيار الصور ← «Send back to the YOLO queue».

## ماذا يحدث عند الأخطاء

- **صورة تالفة أو لا تُقرأ:** تُسجَّل في الخادم بحالة «فشل» مع سبب الخطأ، ويكمل المدير بقية الصور.
- **الخادم متوقف أو الشبكة منقطعة:** يعيد المحاولة كل بضع ثوانٍ، حتى 60 ثانية بين المحاولات.
- **إيقاف المدير بـ Ctrl+C أثناء المعالجة:** الصور المحجوزة تعود إلى الطابور تلقائياً بعد 10 دقائق.
- **مفتاح API خاطئ:** يتوقف برسالة واضحة.

## ملاحظات

- **إذا كان المدير على جهاز آخر،** فهو يُنزّل الصور عبر رابط `/media/`. Django يقدّم هذه الروابط فقط عندما يكون `DEBUG` مفعّلاً. في النشر الفعلي يجب أن يقدّمها خادم ويب.
- **الصور التجريبية من `seed_demo` رسومات SVG،** فيرفضها المدير برسالة «Cannot read image». هذا متوقع؛ استعملوا صوراً حقيقية.
